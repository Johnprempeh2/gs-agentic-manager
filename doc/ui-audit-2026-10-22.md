# UI audit, 22 October 2026 (night pass 1)

Scope: the board UI in a local sandbox seeded with a realistic company
(Northwind Studio: 4 agents incl. a CEO, 2 projects with leads, 34 tasks across
every status with sub-tasks, blockers, key tasks, two pinned tasks, a question
to the board, a review, a chat with the CEO, a goal tree). Every screen below was
captured in light and dark mode at 1440 and 390 wide.

Screens: sidebar and top bar, Dashboard, Desk (Pinned, Needs me), Needed from
you, Tasks list, task page, task tree, project page and project tree, Goals,
Inbox, Settings, Agents list, agent page, chat, new task dialog, search (Cmd+K).

Screenshots: `doc/ui-audit-2026-10-22/` (`before-*` and `after-*`, `-d` desktop
1440, `-m` phone 390).

## How it was measured

- **Contrast.** An in-page probe walks every element with its own text,
  composites its colour (including every ancestor's opacity) over its real
  background stack, and computes the WCAG ratio (4.5:1 body, 3:1 large). Each
  run plants a known failure (#999 on #fff, 2.85:1) and the run only counts if
  the plant is reported. It caught the plant on all 68 screen captures.
- Backgrounds painted with a gradient are flagged as uncertain; those were
  checked by sampling the screenshot pixels instead (the user chat bubble is
  7.3:1 at its lightest, the logo tile 8.5:1). Both are false positives.
- **Focus.** A second probe tabs through the page and records whether each
  focused element shows an outline or a non-transparent box-shadow ring, after
  the 350 ms transition. Read before the transition ends it reports "no ring" on
  every button, which proved it can see a missing ring.
- **Phone.** Sideways scroll (`scrollWidth` against the viewport) and tap targets
  under 40 px. No screen scrolls sideways at 390.

## Pass 2 (night of 22 October)

Same sandbox and seeded company as pass 1, same probes (contrast with a
planted 2.85:1 failure that every run caught, phone overflow), plus two new
ones:

- **Tap area.** On a 390 wide touch phone, for each control, `elementFromPoint`
  walks out from the centre until the point stops landing on the control, so
  the invisible `::before` hit layers count. Before the change it reported the
  status icon at 28 px, matching the documented 28 px layer, which proves it
  sees hit layers.
- **Spacing and borders.** The gap from the page bar to the first section and
  between top-level sections, and the contrast of each bordered panel's border
  and fill against the canvas behind it.

Screenshots: `doc/ui-audit-2026-10-22/p2-before-*` and `p2-after-*` (`-d`
1440, `-t` 1024, `-m` 390; `hit-*` show the measured tap box dashed in red).
