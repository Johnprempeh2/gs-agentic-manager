# Website collections, fields version 1

The Collections tab edits `website_entry` rows for products, categories, public team cards, redirects, forms and vendors. Each saved document body is the collection's `fields` object. The tab builds inputs from the engine's JSON Schema, pinned to greatstone-website merge commit `bb35ff3` in `packages/shared/src/website-collections-v1.json` and `website-collections-manifest-v1.json`. Update both snapshots when the engine publishes a new `fieldsVersion`. The server validates the same schema on create, save and approval.

Saving makes a new document revision and returns the entry to draft. A reviewer can send a saved draft for review. A person with `website:publish` can approve that revision. Approval does not publish or deploy; the release workflow must include the approved revision. Archive keeps the document and its history. Restoring a historic version loads its fields into the editor, where Save draft makes a new revision.

The optional **Import public content as drafts** action copies a dated public snapshot from the engine's `next-proof/release-schema/import-source.mjs`: 10 vendors, 32 categories, 24 products, six public About-page cards and three form definitions. It skips entries whose collection and key already exist, and every imported entry remains a draft. The product snapshot is partial, captured 22 October 2026. A complete catalogue cutover needs the engine's `publishedCatalogue()` database path and a row-count comparison. No Studio staff account, email, invitation or permission data is copied. Current form blocks still render their Puck page props, so editing a form entry alone cannot change the live form until the engine binds those blocks to the collection. No live site is changed by this tab or import.
